== What this handoff is about

AffineScript still needs to emit `typedwasm.access-sites`. The verifier
already consumes the carrier; without AffineScript producer emission,
L2-per-instruction enforcement cannot fire on its emitted bytes.

== The AffineScript blocker

The AffineScript IR / codegen pipeline has typed access at the **type**
level — `lib/borrow.ml` resolves `(region, field)` at typecheck.
By the time codegen emits `i32.load offset=N` /
`i32.store offset=N`, the semantic `(region_id, field_id)`
annotation is gone — codegen recomputes offsets from a local layout
table and the binding is lost between the two passes.

Without `(region_id, field_id)` available at each emit site, there is
nothing to put in the carrier entries.

=== Three resolution options

. **IR annotation** — add resolved `(region_id, field_id)` to the
  typed-access AST/IR variant. Populated by the typechecker, consumed
  by codegen. Cleanest; minimal coupling between the two passes.
. **Side-table** — typechecker produces `Map<expr_id, (region_id,
  field_id)>`, codegen consults during emission. Less invasive to
  AST/IR shape; adds a parameter to the codegen entry function.
. **Re-resolve at codegen** — duplicate typechecker resolution
  logic in codegen. Code smell; avoid unless 1 + 2 are both blocked
  (e.g. by AST stability constraints).

The owner has not selected between 1 / 2 / 3 for AffineScript.
Ephapax's fixed string schema lets codegen identify the fields without
threading; that does not settle the choice for AffineScript's
user-declared regions.

== The encoder (~25 LOC, mechanical)

Wire format per typed-wasm proposal 0002 §"Wire format":

[source]
----
u16le    version                  (= ACCESS_SITES_VERSION = 1)
uleb128  entry_count              (unsigned LEB128 over u32)
for each entry (in producer-emission order):
    uleb128  func_idx
    uleb128  instruction_byte_offset  (byte offset from the start of the
                                       function body's locals vector;
                                       u32::MAX = declared-only, unpinned)
    uleb128  region_id
    uleb128  field_id
----

Only `version` is fixed-width little-endian. `entry_count` and all four
entry fields are unsigned LEB128 (shortest encoding), per proposal 0002
§"Wire format" (encoding option B, ~5 B per access, ~1.1% module
overhead). A producer that writes them as fixed-width `u32le` emits a
carrier the verifier decodes as different values.

The encoder is straightforward — pattern-match on the precedents:

* AffineScript: extend `lib/tw_section.ml` / `lib/tw_section.mli`
  with `Encode.access_sites : (int * int * int * int) list -> bytes`.
  The forward-compat slot is already declared in the `.mli` header
  (refreshed in affinescript#468).
* Ephapax: `src/ephapax-wasm/src/carriers.rs` already encodes the
  string-runtime access sites and can be used as a reference.

== Coordination notes

* **The encoder is the easy half.** Don't be tempted to land
  `Encode.access_sites` first as a "minimal slice" — without the
  threading, it has no feeder.
* **Field IDs must be stable across producers consuming the same
  shared schema** (cross-module case). When a region is imported
  from another module, the importer's `field_id` numbering must
  match the exporter's — this is what the typed-wasm verifier's
  `verify_access_sites_from_module` checks via the
  `typedwasm.regions` cross-reference. If the typechecker assigns
  field IDs from a per-module counter, the cross-module case will
  fail. Confirm the ID scheme is shared-schema-aware before relying
  on it.
* **No new wire-format proposals.** This is implementation of
  already-accepted proposal 0002 / ADR-0003. If the threading work
  surfaces a wire-format gap, file a proposal-0002 amendment issue
  rather than improvising.
